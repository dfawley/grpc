# Resolved review items

Review items from the gRPC spec draft that are closed. Open items are in [review_items.md](review_items.md); implementation bugs are in the bug lists ([Go](bugs_go.md), [Java](bugs_java.md), [C++](bugs_cpp.md), [documentation](bugs_docs.md)).

Investigated items were resolved when Java, Go, and C++ agreed, the behavior was reasonable, and no written spec (gRFC, doc, or proto) contradicted it. The inline REVIEW comment was removed and the spec text was aligned with the implementations. Item numbers are from the original 202-item list.
Total resolved by investigation: **45**. Closed without investigation: **24**.


## Core semantics and status codes

- **Item 5** (`02-rpc-semantics.md §2.8.3`)
  - **Finding:** Java: automatic via `io.grpc.Context` (`ClientCallImpl`). Go: through `context.Context` passed from the handler. C++: opt-in via `ClientContext::FromServerContext` (defaults include deadline and cancel). All three fit "MUST be possible, SHOULD be default where a call context exists".
  - **Spec change:** Comment deleted.
- **Item 7** (`02-rpc-semantics.md §2.10.1`)
  - **Finding:** Out-of-range grpc-status. Go passes it through (`http2_client.go`). C++ passes it through (`metadata_batch.h`). Java converts to UNKNOWN because its enum cannot represent it (`Status.java`). All fit the spec text. Side note: unparseable grpc-status is UNKNOWN in Java/Go but INTERNAL in C++ (hpack parse error); spec (§3.1.6.3) says UNKNOWN, per statuscodes.md.
  - **Spec change:** Comment deleted.
- **Item 9** (`02-rpc-semantics.md §2.12`)
  - **Finding:** All three check both the wire length and the decompressed length, and stop decompressing early. Java: `MessageDeframer`/`SizeEnforcingInputStream`. Go: `rpc_util.go` LimitReader. C++: `frame_data.cc`, `message_compress.cc`, `message_size_filter.cc`. (Java's lazy decompressed check surfaces as CANCELLED/UNKNOWN, not RESOURCE_EXHAUSTED.)
  - **Spec change:** Comment deleted.
- **Item 22** (`http2.md §3.1.3.7`)
  - **Finding:** Unparseable grpc-timeout. Java: RST(INTERNAL_ERROR), so the client sees INTERNAL. Go: early abort with grpc-status INTERNAL (`http2_server.go`). C++: Trailers-Only INTERNAL. (C++ accepts 9-digit values.)
  - **Spec change:** Comment deleted.
- **Item 25** (`http2.md §3.1.5`)
  - **Finding:** Flag=1 without encoding: INTERNAL in all three (`MessageDeframer`; `rpc_util.go`; `compression_filter.cc`). Side note: for flag values other than 0/1, Java and Go give INTERNAL, but C++ appears to drop the message silently (`frame_data.cc`; from reading the code, untested).
  - **Spec change:** Comment deleted.
- **Item 27** (`http2.md §3.1.6.4`)
  - **Finding:** All three decode both hex cases and encode uppercase (`Status.java`; `http_util.go`; `percent_encoding.cc`).
  - **Spec change:** Comment deleted.

## HTTP/2 transport

- **Item 17** (`03-wire-protocol/02-http2-transport.md (3.2.4.1)`)
  - **Finding:** All cumulative, channel-wide, replace only if larger. Java: AtomicBackoff.State.backoff() doubles the value the transport was created with (NettyChannelBuilder, core/internal/AtomicBackoff.java). Go: `2*ac.dopts.copts.KeepaliveParams.Time`, max with cc value (clientconn.go adjustParams). C++: transport doubles its keepalive_time (capped at INT_MAX ms), Subchannel::ThrottleKeepaliveTimeLocked keeps max.
  - **Spec change:** Clarified: doubles the value the GOAWAY'd connection used, replaces only if larger, no bound beyond overflow. REVIEW removed.
- **Item 23** (`03-wire-protocol/01-http2.md (3.1.3.10)`)
  - **Finding:** All prepend app UA + space. Java: GrpcUtil.getGrpcUserAgent. Go: `s + " " + grpcUA` (dialoptions.go WithUserAgent). C++: primary UA, then grpc-c/..., then secondary UA (http_client_filter.cc).
  - **Spec change:** Reworded to state the behavior ("is placed before ..."); REVIEW removed.
- **Item 33** (`03-wire-protocol/01-http2.md (3.1.9.2)`)
  - **Finding:** All send GOAWAY(2^31-1), then PING, then the final GOAWAY on the ACK or a timer. Go: 5s timer (http2_server.go goAwayPing). Java: 10s (NettyServerHandler GRACEFUL_SHUTDOWN_PING_TIMEOUT). C++: ping timeout ≤20s (chttp2_transport.cc GracefulGoaway).
  - **Spec change:** No text change; REVIEW removed.
- **Item 34** (`03-wire-protocol/01-http2.md (3.1.9.3)`)
  - **Finding:** Client: UNAVAILABLE in all (Java KeepAliveManager.onPingTimeout; Go connectionErrorf in http2_client.go; C++ UnavailableError("keepalive timeout")). Server: connection closed, calls cancelled (Java forcefulClose UNAVAILABLE internally → onCancel; Go t.Close → ctx canceled; C++ same).
  - **Spec change:** No text change; REVIEW removed.
- **Item 35** (`03-wire-protocol/01-http2.md (3.1.9.5)`)
  - **Finding:** All fail the connection without h2 ALPN, on both client and server. Java: ProtocolNegotiators (client: "Failed ALPN negotiation"; server check at ~L462). Go: credentials/tls.go client+server (EnforceALPNEnabled defaults true; temporary env guard). C++: grpc_ssl_check_alpn in tls/ssl security connectors (client+server).
  - **Spec change:** SHOULD→MUST, now covers clients and servers; REVIEW removed.
- **Item 36** (`03-wire-protocol/01-http2.md (3.1.9.5)`)
  - **Finding:** All use prior knowledge for plaintext by default. Java also has an opt-in client NegotiationType.PLAINTEXT_UPGRADE (h2c upgrade), not the default. Go/C++: prior knowledge only.
  - **Spec change:** No text change; REVIEW removed.
- **Item 110** (`05-server.md (5.3.2)`)
  - **Finding:** All send Trailers-Only for any status (OK included) when no headers or messages were sent. Go: writeStatus with no header md (http2_server.go). Java: close() without sendHeaders → trailers-only (ServerCalls onCompleted with no messages). C++: writing.cc converts default initial md to Trailers-Only.
  - **Spec change:** Added "whatever the status is, including OK for a streaming RPC that sends no response messages"; REVIEW removed.

## Resolved by owner decision (items R1–R50)

These items were resolved by applying the owner's decision: either the recommendation in review_items.md or an explicit override. Bugs found along the way are in the bug lists ([Go](bugs_go.md), [Java](bugs_java.md), [C++](bugs_cpp.md), [documentation](bugs_docs.md)).

- **R1. Invalid and reserved metadata from the application** — resolved. Kept the spec as written (invalid entries MUST NOT be sent, SHOULD error, MAY drop; the library's value wins for reserved keys it sets; other reserved keys are unspecified). Removed the comment from 02-rpc-semantics. Bugs: none.
- **R2. Status for oversized received metadata** — resolved. Kept SHOULD `RESOURCE_EXHAUSTED` on both sides in 02-rpc-semantics "Size Limits" (consistent with http2.md "Header list size"). Removed the comment. Bugs: Go: Oversized metadata not reported as RESOURCE_EXHAUSTED; Java: Netty hard header-size limit yields INTERNAL instead of RESOURCE_EXHAUSTED.
- **R3. Rich error details whose code doesn't match grpc-status** — resolved (owner override). Left the spec text unchanged, since "the receiver" may be the application or the library, and removed the comment from 02-rpc-semantics. (The 02 Status API requirement now also requires access to the raw trailer, per R10.) Bugs: none.
- **R4. Interceptor ordering** — resolved (owner override). 02-rpc-semantics "Ordering" now defines outermost/innermost by nesting and says how registration order maps to nesting is implementation-defined. Removed the "in a defined order"/"in order" wording in 02 (client interceptors, API requirements), 05-server (interceptor ordering paragraph, API requirements), and 01-architecture (server interceptors step). The spec no longer says "first"/"last" registered anywhere. Bugs: none.
- **R5. Clients sending SETTINGS_ENABLE_PUSH=0** — resolved. Kept "clients SHOULD send 0" in http2-transport "SETTINGS sent". Removed the comment. Bugs: Go: Client does not send SETTINGS_ENABLE_PUSH=0.
- **R6. Configurability of MAX_PING_STRIKES** — resolved. In http2-transport, the settings table now says implementations MAY make it configurable and that 0 SHOULD mean unlimited if they do. The API Requirements line changed from MUST to MAY. Removed the comment. Bugs: none.
- **R7. TCP_USER_TIMEOUT on servers** — resolved. Kept the requirement for both clients and servers, already scoped to platforms that support the option (http2-transport "TCP_USER_TIMEOUT"). Removed the comment. Bugs: Java: Servers never set TCP_USER_TIMEOUT.
- **R8. Server header and client "max pings without data"** — resolved. Both remain out of the spec (http2-transport). Removed the comment. Bugs: C++: Client "max pings without data" throttle on by default.
- **R9. Oversized headers (wire level)** — resolved. Kept http2.md "Header list size" as written (SHOULD RESOURCE_EXHAUSTED, reset as a fallback, SHOULD advertise the limit). Removed the comment. Bugs: Go: Server header-size handling and SETTINGS_MAX_HEADER_LIST_SIZE advertisement (client status code covered under R2).
- **R10. grpc-status-details-bin code mismatch (wire level)** — resolved (owner override). http2.md "`grpc-status-details-bin`" now says the details' code and message MUST match `grpc-status`/`grpc-message`, that the library MAY check this (and act on a mismatch) but is not required to, and that the application MUST be able to read the raw trailer. Made matching changes in protobuf.md "API Requirements" (dropped "only details that passed the check are exposed"), the 02-rpc-semantics Status API requirement (raw trailer readable), 05-server "Status and Trailers", and the appendix A key table. protobuf.md "Rich Error Details" was already consistent. Bugs: none (Go, Java, and C++ all let applications read the raw trailer).
- **R11. Status when the stream ends without trailers** — resolved. Kept INTERNAL for END_STREAM on a DATA frame (no trailer block) and UNKNOWN for other missing-grpc-status cases. Added the rationale and made the "200 without grpc-status" bullet consistent in http2.md "Deriving the status". Bugs: C++: Response ending with END_STREAM on a DATA frame reports UNKNOWN instead of INTERNAL.
- **R12. Mapping of unknown and NO_ERROR RST_STREAM codes** — resolved. Kept INTERNAL for unknown codes and for NO_ERROR before trailers. Added to http2.md "RST_STREAM" that NO_ERROR before complete trailers MUST NOT be mapped to UNAVAILABLE or another retryable code. Bugs: Go: Unknown RST_STREAM error code maps to UNKNOWN instead of INTERNAL; Java: Netty client maps RST_STREAM(NO_ERROR) before trailers to UNAVAILABLE.
- **R14. Receiver checks on rich error details (protobuf mapping)** — resolved (owner override, same as R10). protobuf.md "Rich Error Details" now says: senders MUST make Status.code/message match grpc-status/grpc-message; receivers MAY check and act on mismatches or unparseable details but aren't required to; applications MUST be able to read the raw grpc-status-details-bin trailer. The http2.md `grpc-status-details-bin` section and 02-rpc-semantics.md "Rich Error Details" (R10/R3) still need to say the same; that is A1's part. Bugs: none.
- **R16. Channel creation with an unresolvable target** — resolved. channel.md "Target URI Parsing" now requires that the error reach the application, either by failing channel creation or by returning a channel on which every RPC fails with that error. The pseudocode comment was updated. Bugs: none.
- **R17. Graceful vs. immediate channel shutdown** — resolved (owner override). channel.md "Channel Shutdown" keeps the universal parts: report SHUTDOWN, new RPCs fail right away regardless of wait_for_ready, resources are released once no RPCs remain. It now says that how shutdown interacts with in-flight and queued RPCs, the set of shutdown operations, and the status code (typically UNAVAILABLE) are language-specific. The API requirement now asks only for "a way to shut the channel down". call-dispatch.md "Failures Before a Config Is Available" and the StartRpc pseudocode were aligned. Bugs: none.
- **R18. Outlier detection with max_ejection_percent = 0** — resolved; revised (owner follow-up, consensus pending). The limit now follows Envoy's default check: eject only if `100 * (ejected + 1) / endpoints <= max_ejection_percent`, so the limit is never exceeded and 0 disables ejection.
